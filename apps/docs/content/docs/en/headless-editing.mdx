## Framekit-owned projects

The headless path works without a running Final Cut Pro session. Framekit owns the project and timeline state; a connected editor or exported artifact does not silently replace it.

## Typical workflow

1. Call `editing.route` for the intended operation.
2. Create or open a project and inspect its current revision with the headless project tools.
3. Register media against the expected revision. Use `headless.media.search` with the project ID to find registered sources by ID, name or path; same-name results remain separate. Then preview an edit before executing it.
4. Reopen and inspect the exact project revision before rendering. Verify the resulting output independently.

A stale revision or unavailable provider requires a fresh inspection or a structured failure. Framekit does not silently substitute a native operation or external renderer. The [video production runbook](https://github.com/morshoto/framekit/blob/main/plugins/framekit/references/tests/codex-video-production-e2e.md) shows a detailed workflow and its evidence boundaries.

If rough-cut execution returns `HEADLESS_ROUGH_CUT_HISTORY_UNCONFIRMED`, the project edit has already committed, but no execution or publish proof was returned. The error includes the project, sequence, execution ID, and committed revision. Reinspect the project before retrying; an error response does not mean the edit was rolled back.

Splitting an occurrence with fades, attachments, or story-element references is unavailable until those structures can be remapped safely. The preview and execution reject such splits without changing the project.

Project writes do not automatically remove an existing project lock, even if its recorded process has exited. This protection requires every writer using the project state to include this behavior. Before sharing state with upgraded writers, stop and drain older writers: they may remove an initializing or replaced lock and allow concurrent writes. An interrupted writer can leave later writes blocked. Before an operator clears such a lock, they must independently establish that no writer can still use it; elapsed time, an empty file, or a PID alone does not prove that.
