## Run the fixture server

For development, install Node.js 22.23.5 and pnpm 12.18.0, then from the repository root:

```sh
pnpm install --frozen-lockfile
pnpm run build
```

Configure your MCP client as follows, replacing `cwd` with the absolute path to your checkout and `FRAMEKIT_STATE_DIR` with an absolute path to a dedicated directory separate from existing projects. Configuration syntax varies by client.

```toml
[mcp_servers.framekit-fixture]
command = "pnpm"
args = ["--silent", "run", "mcp"]
cwd = "/path/to/framekit"
env = { FRAMEKIT_EDITOR = "fixture", FRAMEKIT_STATE_DIR = "/path/to/disposable-framekit-state" }
```

The client starts `pnpm run mcp` and connects its standard input and output (stdio); it cannot attach to a process started separately in a terminal. The fixture editor uses deterministic in-memory data, but the same server's headless project tools can read and write projects under `FRAMEKIT_STATE_DIR`, or `~/.framekit/projects` when it is unset. Use a dedicated state directory to keep experiments separate from existing projects. Use `connection.status`, `editor.inspect`, and `editing.route` to inspect what the selected backend supports.

## Confirm the fixture responds

From the repository root, run:

```sh
pnpm run smoke:fixture-mcp
```

The command starts an isolated fixture server and checks its connection. A successful run prints `Fixture MCP stdio smoke passed: connection.status ready.`

## Validate a checkout

```sh
pnpm run test
pnpm run check:boundaries
pnpm run check:docs
```

For fixture-focused setup and optional Nix profiles, see the [maintained getting-started guide](https://github.com/morshoto/framekit/blob/main/docs/getting-started.md). Fixture behavior is not proof of a native Final Cut edit.
