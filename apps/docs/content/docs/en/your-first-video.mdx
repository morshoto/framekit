Make a two-second video in a new Framekit-owned project, inspect the preview and resulting timeline, and independently check the MP4. This headless example does not open or edit Final Cut Pro. For plugin setup, see [Installation](/en/docs/installation/).

## Prerequisites

The commands below were checked on macOS 26.5.1 with Node.js 22.23.5, npm, FFmpeg/ffprobe 9.0.2, and the published Framekit v0.2.6 server at commit `2f6f03b6a0cba5b5cb5d4a3ea0f44c3ffa9cdf6c`. FFmpeg must provide the `libx264` encoder. Install Git only if you also want a repository checkout; this example does not require one. The published package supports Node.js 20 or newer, but this exact example was checked with the version above.

A separate clean-client smoke test installed the published plugin and used a fixture backend; that fixture test does not verify a real-media render. The direct scripted MCP workflow below was run against the published server with real-media input; it is not a test of the natural-language prompt later on this page.

## Download the sample and tools

[Sample Flash Animation](https://commons.wikimedia.org/wiki/File:Sample_Flash_Animation.webm) by H0iadfpwijdf is an original work dedicated to the public domain under [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/). It is 14,384 bytes. Create a new directory, install the pinned MCP client and Framekit package, and download the sample and example client:

```sh
mkdir framekit-first-video
cd framekit-first-video
npm install --no-save --no-package-lock @morshoto/framekit@0.2.6 @modelcontextprotocol/sdk@1.32.2
curl -fL -o sample.webm 'https://commons.wikimedia.org/wiki/Special:FilePath/Sample_Flash_Animation.webm'
curl -fL -o first-video.mjs https://raw.githubusercontent.com/morshoto/framekit/3384746981703e8a03adc9007df01dc89a615916/apps/docs/public/examples/first-video.mjs
shasum -a 256 sample.webm
```

The source SHA-256 must be `e96efec0c3bf57836b54cbead8d195564ee4e1303a320b343b4fda6642ce5904`. Stop if it differs. The client also checks that digest before creating a project. The npm command and downloads write only within the new example directory and normal npm cache.

## Preview and render

```sh
node first-video.mjs sample.webm
```

The client starts the pinned package in headless mode with automatic connection disabled, ignores inherited Final Cut socket and FCPXML settings, creates a disposable project, registers the source, and prints the proposed timeline and a new output path. It then asks for confirmation. Review the one `sample-shot` occurrence, starting at zero and lasting two seconds. Type `yes` to execute that same revision-bound edit and render; any other answer stops before edit execution and rendering. Project creation and media registration already write to the new Framekit-owned state directory. A successful run prints `Result: passed` and the directory containing `first-video.mp4` and `evidence.json`.

The observed tool sequence was `headless.project.create`, `headless.media.register`, `headless.edit.preview`, `headless.edit.execute`, and `headless.render`. The render response and its verification both reported `passed`. If execution or verification fails, inspect the error and retained state before deciding what to do; do not blindly repeat an uncertain operation.

## Inspect and verify

Change into the output directory printed by the program. To inspect the saved Framekit timeline before and after the edit:

```sh
node --input-type=module <<'NODE'
import { readFileSync } from 'node:fs';
const evidence = JSON.parse(readFileSync('evidence.json', 'utf8'));
console.log('Before:', JSON.stringify(evidence.before, null, 2));
console.log('After:', JSON.stringify(evidence.after, null, 2));
NODE
```

In the observed run, the starting sequence had no occurrences and the resulting sequence had one two-second occurrence. Open `first-video.mp4` in a player. This frame was extracted from an earlier v0.2.6 headless render of the same CC0 source and edit, not from Final Cut:

![A stick figure from the rendered CC0 animation](/images/first-video-cc0-output.png)

Independently probe the output:

```sh
ffprobe -v error -show_entries stream=codec_type,width,height,r_frame_rate -show_entries format=duration -of json first-video.mp4
```

The observed output contained 400 × 290 video at 12 fps, an audio stream, and a duration of `2.000000` seconds. Metadata alone does not prove visual or audio correctness; inspect playback as well. `evidence.json` can contain local paths: remove personal information before sharing it.

## If something fails

Check the first failing message and installed versions. Missing FFmpeg, an encoder, or a renderer capability can prevent rendering. Use [Troubleshooting](/en/docs/troubleshooting/) for symptom-based checks and the [Error Reference](/en/docs/error-reference/) for coded errors. The MP4 is a headless output; FCPXML is a separate handoff artifact, and neither proves import, playback, or an edit in Final Cut Pro.
